Behaviors in C++

A behavior can be written in C++ instead of a script language. It lives in the Engine part of the project’s own plugin, and runs as a script’s behavior does: the same kinds, the same lifecycle, events, messages and property overrides, and the same calls into the engine. A project can mix C++ behaviors with scripted ones, or have no script language at all.

Writing one

Section titled “Writing one”

The class derives from engine::behavior::RunBehavior, SceneBehavior or EntityBehavior, and reflects itself:

  • Its handlers are the reflected methods named as a script’s are: onStart, onUpdate, onHit for the hit event, onPing for the Ping message.
  • Its properties, which the inspector shows and an entity or a scene can override, are the reflected fields it marks behaviorProperty. A field it does not mark is its own.
  • builder.Creator() tells the engine how to make one.

An entity behavior reads its entity with Self(), and a scene behavior its scene with GetScene(). Both are the same handles a script holds, so Self().setPosition(...) reads as a script’s self.setPosition(...), and the engine’s other calls a script makes work from C++ too. Fault(reason) disables the behavior, as a script error disables a script’s.

Using it

Section titled “Using it”

File > New, under Scripts, then Native Behavior makes the class’s asset. Name the asset like the class: the asset Bobber names the registered class Bobber. The asset is then set where a script’s is: in an entity’s Behavior component, in a scene’s Scene Behavior settings, or as the project’s Run behavior. Build the plugin and reload it first (Project > Build Project Plugins, then Project > Reload Project Plugins), so the editor knows the class.

How it differs from a script

Section titled “How it differs from a script”
  • It changes only when its plugin is built and reloaded, while nothing runs; a script reloads as you save it.
  • A crash in it is a crash of the game, not a script error. The crash report names the behavior it was in, as in: Bobber.onUpdate on 'cube'.
  • Scripts do not see a C++ behavior by name. They reach it through messages and events, as they reach one another.

Calling a C++ behavior’s handler costs about what calling a script’s does, since the engine calls every behavior the same way; the work inside it runs as native code. Gameplay that runs on many entities every frame is cheaper as a component and its scene system, in the same plugin.

Agents

Section titled “Agents”

native_behavior_list lists the C++ behavior classes the plugins register: each one’s name, kind, properties with their defaults, handlers, and the project’s assets that name it. asset_create with the Native Behavior creator and the class’s name makes its asset.
