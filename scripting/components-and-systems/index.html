Components and systems in C++

A project can add its own components to the engine, with the code that updates them, in the Engine part of its plugin. The engine’s own components work the same way, so a project’s component appears in Add Component and the inspector, saves with the scene, and is updated every frame as the engine’s are.

The engine keeps data and code apart:

  • A component is plain data on an entity: a struct of values, with no code of its own.
  • A component manager holds every component of one type in a scene, and updates them.
  • A scene system is code that runs for a scene without components of its own. A component manager is a scene system that holds components.
  • A run service is state that lasts for the whole run of the game, across its scenes.

The NativeSample sample project’s Spin component, which turns its entity, is the example on this page.

Its reflection is what the editor reads: the name it shows, the category Add Component lists it under, its description, and the fields the inspector edits.

Its manager

Section titled “Its manager”

A component’s manager derives from SerializableComponentManager<T>, which saves its components with the scene. The name it is given is the one the scene file stores, so it must not change once scenes use it. (ComponentManager<T> is the same without saving, for components that are only made at run time.)

ForEach visits every component with its entity, and Get(entity), Has(entity), Add(entity) and Remove(entity) reach one. A manager hears its components come and go by overriding OnComponentCreated, OnComponentInitialized (at the start of the frame after it was added) and OnComponentDestroyed.

When it runs

Section titled “When it runs”

A scene updates in phases, in this order, and calls each system’s OnUpdate once per phase:

Phase For
Initialize Components added since the last frame are initialized
PreUpdate Reading back physics, applying input
Update Gameplay
AsyncUpdate Work that touches only the system’s own data
PostUpdate Animation, constraints, late logic
PostTransform Work that needs the frame’s final transforms
Cleanup Destruction deferred to the end of the frame

Within a phase, systems run in the order of their UpdateOrder(), lower first (0 by default). OnFixedUpdate(step) runs at the physics step instead of once a frame. OnSceneStarted and OnSceneStopped come as play starts and stops, and OnEntityDestroyed and OnEntityActiveChanged as entities go and are switched on or off.

IsSimulationOnly() returning true keeps the system still while the editor edits the scene; one that should also run while editing (a preview, say) leaves it false.

A scene system

Section titled “A scene system”

Code that runs for a scene without components of its own, such as a spatial index or a director that watches the whole scene, derives from foundation::scene::SceneSystem and overrides the same hooks. Other code finds it in the scene with scene.GetSystem<MySystem>(), as it finds a component’s manager.

Adding them to the engine

Section titled “Adding them to the engine”

The Engine part’s Load registers the component’s reflection and adds the manager to every scene, including scenes already open:

The Engine part links Foundation::Scene and, for EnginePluginServices, Engine::Composition.

What Load adds is taken out again when the plugin unloads. While the plugin is rebuilt and reloaded, the open scenes keep their entities’ components, and get them back with the reloaded manager.

Per-run state

Section titled “Per-run state”

State that belongs to the whole game rather than one scene (a score kept across levels, a connection) is a run service. It may implement foundation::run::IRunService to hear the run: OnRunStarted, OnRunUpdate once a frame, OnRunPaused, OnRunStopping.

Every run gets one, including runs already going. A scene system reaches it through its scene’s run: scene.Run()->Get<ScoreKeeper>().

Using them

Section titled “Using them”

Build the plugin and reload it (Project > Build Project Plugins, then Project > Reload Project Plugins). The component is then in Add Component, under its category, and the inspector edits its fields as it does the engine’s components’. An agent adds and sets it with component_add and component_set, as it does any component.
