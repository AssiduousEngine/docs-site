Writing gameplay

This page shows the script API for the jobs most gameplay needs. The script page’s API list, in the editor, has the rest.

The two languages call the same API in their own way:

  • Luau calls an object’s methods with a colon (self.entity:name()) and the engine’s shared services with a dot (Log.info, Input.isDown).
  • AngelScript uses a dot for methods (self.name()) and :: for services (Log::info, Input::isDown). Engine objects are handles: Float3@, Entity@.

A behavior’s life

Section titled “A behavior’s life”

A behavior is a class. The engine makes one for each entity it is attached to, and calls its methods when there is something to do. Write only the ones you need:

Method Called
onStart() Once, when the entity is in play
onUpdate(dt) Every frame, dt the seconds since the last one
onFixedUpdate(dt) At the physics rate
onEnable(), onDisable() When the behavior is turned on or off
onDestroy() Before the entity goes
onContactBegin, onContactEnd, onTriggerEnter, onTriggerExit On physics contacts (below)
on<Name>(payload) When a message named <Name> arrives (below)

A Level script gets onStart, onUpdate, onFixedUpdate and onStop. A Game script gets launch(), update(dt) and exit().

Scripts update before the systems that act on what they set, so a sound started or a destination set in onUpdate takes effect the same frame.

Moving things

Section titled “Moving things”
  • Luau
  • AngelScript
  • position(), rotation() and scale() and their setters work in the parent’s space. worldPosition(), worldRotation() and worldScale() read where the entity is in the world.
  • setRotationEuler(x, y, z) takes degrees: pitch, yaw and roll.
  • In Luau a Float3 is Luau’s own vector type, made with Float3.new(x, y, z); use Luau’s math library. AngelScript has Math::Sin and the rest.

Input

Section titled “Input”

Scripts read the actions of the project’s input map, by name, never raw keys. That way a player can rebind them, and a gamepad works too.

  • Luau
  • AngelScript

isDown is true while held, wasPressed and wasReleased on the frame it changed. value reads a one-axis action. Input.rumble(low, high, seconds) shakes the gamepad.

Finding entities and their components

Section titled “Finding entities and their components”
  • Luau
  • AngelScript
  • The scene’s find(name) returns the first entity with that name; findByPath("Level/Doors/Front") follows the hierarchy. An entity’s findChildByName, parent(), firstChild() and nextSibling() walk it.
  • Check isValid() before using an entity you found or kept: an entity that was destroyed, or never found, does nothing when called.
  • A component’s of(entity) gives its API on that entity: RigidBodyComponent, CharacterComponent, MeshComponent, LightComponent, CameraComponent, AudioSourceComponent, NavAgentComponent and more. Scene-wide services work the same way with the scene: ScenePhysics.of(scene), ScenePrefabs.of(scene). On an entity without the component it is nil (Luau) or null (AngelScript), so test it before use. If the component is removed while a script still holds it, using it is a script error.

Spawning and destroying

Section titled “Spawning and destroying”
  • Luau
  • AngelScript

spawn also takes a rotation and a parent. destroy() removes the entity and its children at the end of the frame. scene.createEntity(name) makes an empty one.

Messages between scripts

Section titled “Messages between scripts”

send delivers a message to the behaviors of one entity: a message named CoinCollected calls their onCoinCollected method, with the payload if there is one. scene.events.emit does the same for every script listening, Level and Game scripts included.

  • Luau
  • AngelScript

Messages are delivered after the current update, not during the send.

Physics

Section titled “Physics”

Contacts call methods on the behaviors of both entities, each told about the other:

  • Luau
  • AngelScript

onContactEnd takes the same values, and onTriggerExit(other) fires when something leaves a trigger.

Push a body with an impulse, and look for what is below or ahead with a ray:

  • Luau
  • AngelScript

A hit has position, normal, distance and entity(). sphereCast and overlapSphere are there too. A character moves through its CharacterComponent: move, jump, grounded().

Sound

Section titled “Sound”
  • Luau
  • AngelScript

A sound plays by its asset ID (playOneShot, playCue, playMusic) or by its path in the Assets panel (the Path versions). The 3D versions play at a position. The buses are Master, Effects, Music and UI.

Waiting

Section titled “Waiting”

A coroutine runs over several frames, waiting where it needs to:

  • Luau
  • AngelScript

Pass self as the second argument, so the coroutine stops when the behavior goes.

Changing scene

Section titled “Changing scene”

run controls the game as a whole. Load a scene by its ID:

  • Luau
  • AngelScript

The scene that was playing is removed once the new one is in. loadSceneAsync loads in the background (check loadComplete), setTimeScale(0) pauses the game, and requestExit() quits.

The HUD and menus

Section titled “The HUD and menus”

ui shows UI documents and reaches into them by element name:

  • Luau
  • AngelScript

push shows a document over what is there, pop and back remove it, and replace swaps it.

Saving progress

Section titled “Saving progress”

Save keeps values between runs: a best time, an unlocked level, the game’s options. Values are ints, floats, booleans or strings, under any key you choose:

  • Luau
  • AngelScript

The second argument of a get is what it returns when nothing is saved yet. The game writes what changed when it ends; flush() writes now, so a crash loses nothing. Playing in the editor keeps its own save, apart from a player’s.

Logging

Section titled “Logging”

Log.info, Log.warn and Log.error (Log::info and so on in AngelScript) write to the Console in the editor and to the log of an exported game.

Time.delta() and Time.now() give the frame time and the time, and Random.value(), Random.range(a, b) give random numbers.
